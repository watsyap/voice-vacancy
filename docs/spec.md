# A3. Спецификация: голосовая вакансия

Источники: `docs/flow.md` (A2) > `docs/analysis.md` (A1) > `docs/prompts/work-prompts.md` (А0). При расхождении действует источник левее.
Состояния — по ID из `docs/flow.md` §3 (S1–S24). Здесь они не переписываются, только дополняются правилами и критериями приёмки.

---

## 1. Проблема и задача пользователя

Нанимающий менеджер знает, кто ему нужен, но не любит и не умеет писать вакансии. Формы его тормозят, и он отправляет HR голосовое сообщение в мессенджере.
**Задача:** за 3–5 минут проговорить 4 ответа и получить готовый текст вакансии, который можно передать HR почти без правок.

---

## 2. Вопросы

Формулировки исходника написаны про уже работающего сотрудника. Мы переформулировали их под новую вакансию (A1, допущения 2–3). Исходник указываем рядом, чтобы было видно, что требования не изменены молча.

| # | Наш вопрос | Исходник | Пример под вопросом (серым) |
|---|---|---|---|
| Q1 | Какие две-три задачи сотрудник будет выполнять каждый день? | Какие две-три задачи ежедневно он выполняет? | Например: ревью кода, планирование спринта, созвоны с заказчиком |
| Q2 | Над каким проектом он будет работать первые 6 месяцев? | Над каким проектом он работает эти 6 месяцев? | Например: запуск приложения для курьеров, чтобы сократить время доставки |
| Q3 | Что дальше: продолжит этот проект или перейдёт на другой? На какой и с чем он связан? | В ближайшие полгода он продолжит… или возьмётся за другой? Какой именно? | Например: перейдёт на внутреннюю CRM. Или: пока не решили |
| Q4 | Какими инструментами, программами и знаниями он должен владеть? | (без изменений по смыслу) | Например: Figma, SQL, опыт в B2B-аналитике |

Порядок вопросов фиксирован.

## 4. Экран и элементы

Экран один, четыре зоны (flow.md §1). Модалок и попапов нет.

### 4.1 Экран вопроса

| Элемент | Назначение | Правила |
|---|---|---|
| Текст вопроса | Что спрашиваем | Сверху, до 2 строк. Номера нет: позицию показывает кольцо |
| Пример ответа | Снять ступор «с чего начать» | 1 строка, вторичный цвет. Скрывается, когда появился промежуточный текст |
| Кольцо | Прогресс (4 сегмента), обратная связь «слышу», управление записью | Центр — пауза/продолжить (S4/S5/S8). Сегменты — переход к ответу (S15), только в S10/S10′/S12/S14/S20 |
| Подпись статуса | Одна строка: что делает система | «Слушаю», «Пауза», «Разбираю ответ», «Понял: …», тексты ошибок из flow.md |
| Промежуточный текст | Человек видит, что его распознают | Под подписью, до 3 строк, старое уходит вверх с затуханием. Только в S4/S8 |
| «Понял: …» | Показать извлечённое, чтобы ошибку распознавания поймали до генерации | ≤ 2 строки, ≤ 120 символов: перечисление значений слотов. Без процентов и JSON |
| Основная кнопка | Главное действие состояния | «Готово» (S4) · «Следующий вопрос» / «Собрать вакансию» на Q4 (S10/S10′/S12) · «Повторить» (S18) · «Скопировать» (S19) |
| Вторичная кнопка | Откат | «Перезаписать» (S8/S10/S10′/S12) · «Пропустить уточнение» (S11) |
| Ссылки | Выходы, которые не должны конкурировать с основным действием | «Ответить текстом» / «Ответить голосом», «Пропустить». В S11 ссылки «Пропустить» нет: рядом с «Пропустить уточнение» их путают |
| Поле ввода | Текстовый режим | Заменяет промежуточный текст, автовысота до 6 строк, Ctrl+Enter = «Отправить» |
| Метка «Демо-режим» | Честно сказать, что ответы обрабатывает не LLM | Угол экрана, только если сервер вернул `X-Demo: 1`. На S1 метки нет: она появляется после первого ответа API. Отдельный эндпоинт ради метки не добавляем |

Лимит: на экране не больше 1 основной кнопки, 1 вторичной и 2 ссылок.

Горячие клавиши: Enter = «Готово» (голос), Ctrl+Enter = «Отправить» (текст), Esc = пауза.

## 5. Логика полноты (medium)

Модель **только извлекает слоты**, а полноту считает код (A1, критика 1). Поле `score` в API отсутствует.

| Q | Слоты | Обязательные | Полнота |
|---|---|---|---|
| Q1 | `tasks: string[]` | ≥ 2 задачи (действие + объект) | `min(tasks.length, 2) / 2` |
| Q2 | `project: {description, goal, role?}` | `description`, `goal` | заполненные / 2 |
| Q3 | `continuity: "same" \| "other" \| "undecided" \| null`, `next_project: {description, domain}?` | `continuity`; при `other` ещё `description` и `domain` | заполненные / обязательные. `same` и `undecided` → 100% |
| Q4 | `tools: string[]`, `knowledge: string[]` | ≥ 2 пункта суммарно | `min(tools+knowledge, 2) / 2` |

Правила:
- Полнота 100% → S10. Меньше 100% и уточнения ещё не было → S11. Иначе → S10′.
- `off_topic: true` → полнота 0, дальше по тем же правилам.
- Частичный сегмент рисуется минимум на 10% длины, чтобы его можно было отличить от пустого.
- Уточнение показывается только при полноте < 100% и `followup != null`. Если модель вернула `null` — идём в S10′.
- Ответ на уточнение дописывается к исходному транскрипту через пробел. Анализируется объединённый текст.
- «Перезаписать» сбрасывает транскрипт, слоты и флаг уточнения.

**Min-уровень** (до вызова API): длина ответа после нормализации (пробелы, без слов-паразитов «ну», «э», «типа») не меньше порога:

| Вопрос | Порог | Почему |
|---|---|---|
| Q1–Q2 | 5 слов | Задачи и проект не описать короче |
| Q3 | 2 слова | Честный короткий ответ «пока не решили», «тот же проект» — полный (AC-10.4) |
| Q4 | 2 слова | Перечень инструментов короткий по природе: «Figma, SQL» — полный ответ |

Меньше порога → S7. Этот порог заменяет «5 слов» в flow.md §3 (S7) и §4.

## 6. Контракт API (serverless, Vercel)

### `POST /api/analyze`
```
→ { "q": 1|2|3|4, "transcript": string }
← 200 { "slots": {...по §5}, "missing": string[], "followup": string|null, "off_topic": boolean }
```
- Клиент валидирует ответ по схеме §5. Невалидно → 1 повтор, если укладываемся в окно 4 с; иначе S12.
- Любой не-200 или таймаут 4 с → S12. Сервер повторов не делает.
- `missing` и `followup` — на «ты/вы» разговорным языком, без терминов «слот», «скор».
- Продуктовый промт — `docs/prompts/b1-analyze.md`.
- Модель — быстрая (класс Haiku), чтобы укладываться в окно 4 с.

### `POST /api/generate`
```
→ { "answers": [ { "q": 1..4, "status": "analyzed"|"raw"|"skipped",
                   "slots"?: {...}, "transcript"?: string } ] }
← 200 text/plain; charset=utf-8, поток (chunked) Markdown
```
- `raw` (ответ из S12 или из оффлайн-очереди) передаётся транскриптом, извлечение делает модель генерации.
- `skipped` → раздел в тексте отсутствует.
- Все 4 `skipped` клиент не отправляет (S20).
- Структура и ограничения — `docs/prompts/b2-generate.md`: только факты из ответов, без зарплат и «дружного коллектива», до 1500 знаков.
- Модель — класс Sonnet: качество текста важнее скорости, ожидание закрыто стримингом.

### Лимит запросов
С одного IP: `/api/analyze` — 60 в час, `/api/generate` — 10 в час. Одна сессия — до 13 запросов анализа (4 ответа + 4 уточнения + повторы) и 1–2 генерации; лимит пропускает 3–4 прохода в час из одного офиса. Превышение → 429, клиент ведёт себя как при ошибке (S12 / S18).

### Демо-режим
Нет ключа LLM в env → оба эндпоинта работают на эвристиках и ставят заголовок `X-Demo: 1`. Ответ должен **реагировать на ввод**:
- Q1, Q4: деление по запятым, «и», точкам. Q4 дополнительно сверяется со словарём инструментов (Figma, Jira, SQL, Python, 1С, Excel…).
- Q2: `description` = первое предложение; `goal` заполнен, если есть «чтобы», «для», «цель».
- Q3: «продолж», «тот же» → `same`; «не знаю», «не решили», «зависит», «посмотрим» → `undecided`; «другой», «перейд» → `other`.
- `followup`: шаблон по первому пункту `missing`.
- Роль: по словарю Q4 — Figma/Sketch → «Дизайнер»; SQL/Python/Excel/Power BI → «Аналитик»; JavaScript/React/Java/Go/1С → «Разработчик»; Jira/Confluence без других совпадений → «Менеджер проекта». Совпадений нет → «Специалист». Всегда с пометкой «(предположение)».
- Генерация: тот же Markdown-шаблон, заполненный слотами; отдаётся потоком по 20 символов раз в 30 мс.

## 8. Анимация кольца

Геометрия: Ø 240 px (≥ 600 px ширины) / 200 px (мобильный), 64 штриха (по 16 на сегмент), зазор между сегментами 4°. Штрих: 2 px × 8 px, скругление.

| Состояние сегмента | Вид |
|---|---|
| пусто | штрихи `--ring-idle` (низкий контраст) |
| текущий | штрихи `--ring-active`, лёгкое «дыхание» opacity 0.6↔1, 2 с, ease-in-out |
| заполнен | все 16 штрихов `--ring-done` |
| частично | доля штрихов `--ring-done`, остальные `--ring-idle` |
| пропущен | каждый второй штрих скрыт (пунктир) |
| без анализа | все штрихи `--ring-done` с opacity 0.45 |

| Событие | Анимация | Длительность | Easing |
|---|---|---|---|
| Голос (S4) | Длина штрихов текущего сегмента 8 → 8 + 12·RMS px. RMS из `AnalyserNode`, сглаживание: атака 50 мс, спад 150 мс | каждый кадр (rAF) | — |
| Фолбэк громкости (S24) | Импульс по всем штрихам сегмента при каждом новом фрагменте распознавания | 300 мс | ease-out |
| Анализ (S9) | Яркий участок в 4 штриха бежит по сегменту | цикл 1,2 с | linear |
| Заполнение (S10/S10′) | Штрихи загораются по часовой стрелке, по одному | 400 мс на сегмент | cubic-bezier(0.22, 1, 0.36, 1) |
| Переход к вопросу | Текст вопроса: fade + сдвиг 8 px | 250 мс | ease-out |
| Замыкание (S16) | Все 64 штриха вспыхивают волной по кругу, кольцо уменьшается до 48 px и уходит вверх | 600 мс | cubic-bezier(0.22, 1, 0.36, 1) |
| Генерация (S16–S17) | Как анализ, но по всему кольцу | цикл 1,6 с | linear |

`prefers-reduced-motion: reduce`: без вращения и волн. Громкость меняет только opacity штрихов (0.5–1), заполнение мгновенное, переходы — только fade 150 мс. Статус по-прежнему передаётся подписью.

## 9. Критерии приёмки

Только ключевые состояния. Остальные состояния считаются готовыми, если поведение совпадает с flow.md §3.

### S4 — Слушаю
- **AC-4.1** Дано: показан вопрос, микрофон разрешён. Когда: прошло 300 мс. Тогда: запись идёт, подпись «Слушаю», текущий сегмент в состоянии «текущий».
- **AC-4.2** Дано: S4. Когда: пользователь говорит. Тогда: штрихи меняют длину не позже чем через 100 мс, промежуточный текст появляется не позже чем через 1 с.
- **AC-4.3** Дано: в S4 сказано ≥ 1 слово. Когда: 4 с тишины. Тогда: ответ завершается, переход к проверке min.
- **AC-4.4** Дано: S4. Когда: пользователь говорит «проект готов к запуску». Тогда: запись не останавливается.
- **AC-4.5** Дано: Android Chrome, распознавание само остановилось. Когда: оно перезапустилось. Тогда: ранее распознанный текст на экране и в ответе сохранён.

### S7 — Слишком короткий ответ
- **AC-7.1** Дано: Q4, ответ «Figma, SQL». Когда: «Готово». Тогда: S9, а не S7.
- **AC-7.2** Дано: Q1, ответ из 4 слов. Когда: «Готово». Тогда: S7, текст сохранён.

### S9 — Анализ
- **AC-9.1** Дано: ответ не короче порога min (§5). Когда: нажато «Готово». Тогда: не позже чем через 100 мс подпись «Разбираю ответ», сегмент вращается, кнопок нет.
- **AC-9.2** Дано: API отвечает невалидным JSON за 1 с. Когда: анализ. Тогда: ровно 1 повтор; при повторной ошибке → S12.
- **AC-9.3** Дано: API не ответил. Когда: прошло 4 с. Тогда: S12, запрос отменён (AbortController).

### S10 — Понял (полно)
- **AC-10.1** Дано: один и тот же ответ анализируется 5 раз с одинаковыми слотами. Тогда: заполнение сегмента и решение об уточнении идентичны все 5 раз.
- **AC-10.2** Дано: все обязательные слоты (§5). Тогда: сегмент заполнен на 100%, подпись «Понял: …» ≤ 120 символов, без процентов и терминов.
- **AC-10.3** Дано: S10. Когда: прошло 60 с без действий. Тогда: экран не переключился сам.
- **AC-10.4** Дано: Q3, ответ «пока не решили». Тогда: `continuity = undecided`, S10 без уточнения.

### S11 — Уточнение
- **AC-11.1** Дано: Q1, названа 1 задача, уточнения не было. Тогда: сегмент на 50%, показан уточняющий вопрос, запись стартует через 600 мс.
- **AC-11.2** Дано: S11. Когда: пользователь назвал ещё задачу. Тогда: на анализ уходит исходный текст + новый, обе задачи в «Понял».
- **AC-11.3** Дано: после уточнения ответ всё ещё неполный. Тогда: S10′, второго уточнения нет.
- **AC-11.4** Дано: S11. Когда: «Пропустить уточнение». Тогда: S10′ с текущей частичной полнотой.

### S12 — Анализ упал
- **AC-12.1** Дано: ошибка API или таймаут. Тогда: сегмент «без анализа», подпись «Ответ сохранён» + ≤ 80 символов транскрипта, доступны «Следующий вопрос» и «Перезаписать».
- **AC-12.2** Дано: на вопросе статус S12. Когда: генерация. Тогда: этот ответ уходит как `raw` и попадает в соответствующий раздел вакансии.

### S16 — Генерация
- **AC-16.1** Дано: Q4 в S10/S10′/S12/S14, хотя бы один ответ не пропущен. Когда: «Собрать вакансию». Тогда: анимация замыкания 600 мс, затем текст появляется по мере поступления, без ожидания конца.
- **AC-16.2** Дано: Q2 пропущен. Тогда: в тексте нет раздела «Проект».

### S17 — Генерация долгая
- **AC-17.1** Дано: S16. Когда: 10 с без первого фрагмента. Тогда: подпись «Ещё немного…».
- **AC-17.2** Когда: 30 с без первого фрагмента. Тогда: S18.

### S18 — Генерация упала
- **AC-18.1** Дано: ошибка генерации. Тогда: «Не получилось собрать вакансию. Ответы сохранены», кнопка «Повторить».
- **AC-18.2** Дано: S18. Когда: перезагрузка страницы. Тогда: S23, все 4 ответа на месте.

### S19 — Вакансия
- **AC-19.1** Дано: S19. Тогда: роль подписана «(предположение)», в тексте нет слов «зарплата», «бонус», «дружный коллектив», если их не было в ответах; длина ≤ 1500 знаков.
- **AC-19.2** Когда: «Скопировать». Тогда: в буфере Markdown, совпадающий с текстом в редакторе, подпись «Скопировано» 2 с.
- **AC-19.3** Дано: пользователь правил текст. Когда: перезагрузка через ≥ 500 мс после правки. Тогда: правки на месте.

### S21 — Оффлайн
- **AC-21.1** Дано: S4. Когда: сеть пропала. Тогда: не позже чем через 1 с строка «Нет сети…», переход в текстовый режим, уже распознанный текст в поле.
- **AC-21.2** Дано: оффлайн, ответ отправлен. Тогда: сегмент «без анализа», можно идти дальше.
- **AC-21.3** Дано: в очереди 2 ответа. Когда: `online`. Тогда: оба проанализированы по порядку, сегменты обновились без действий пользователя, голос снова доступен.

## 10. Чего делать нельзя

- Модалки, попапы, тосты с действиями. Всё — состояниями кольца и подписи.
- Показывать пользователю JSON, скоры, проценты, слова «слот», «LLM», «модель».
- Использовать оценку полноты от модели. Только расчёт по §5.
- Больше одного уточнения на вопрос.
- Автопереход к следующему вопросу.
- Блокировать сценарий ожиданием анализа дольше 4 с.
- Терять ответы при любой ошибке, перезагрузке, оффлайне.
- Запрашивать микрофон без жеста пользователя.
- Голосовые команды для управления.
- Добавлять в вакансию факты, которых нет в ответах.
- Менять порядок вопросов и добавлять новые.
- Отправлять аудио на наш сервер: на API уходит только текст.

## 11. Что вырезано и почему

| Вырезано | Почему |
|---|---|
| Скор 0–100 от LLM | Нестабилен, уточнения появляются случайно, нельзя протестировать (A1) |
| Форма ответа для уровня min | Противоречит минимализму; min = непустой ответ не короче порога (§5) |
| Озвучка вопросов (TTS) | Мешает в open space, накладывается на микрофон, нет в требованиях |
| Голосовые команды | Ложные срабатывания на обычной речи |
| Автопереход | Не успевают прочитать «Понял» → ошибки уходят в вакансию |
| Возврат к ответам после генерации | Перегенерация затрёт ручные правки |
| Точечная правка слотов | Дорого в UI; перезапись ответа + правка финального текста закрывают задачу |
| Публикация, интеграции, аккаунты, история вакансий | Вне требований |
| Другие языки | Аудитория русскоязычная |
| Серверный STT | Правильно для продакшена, но не за 24 часа (§13) |

## 13. Открытые вопросы и допущения

**Допущения** (подробно — A1 §4):
- Результат — описание вакансии, а не «резюме» из текста задания.
- Q2/Q3 трактуются как «первые полгода → что дальше», а не «прошлые полгода → следующие».
- Основная платформа — десктопный Chrome. Мобильные поддерживаются, но не в приоритете.
- Уточнение показывается текстом, отвечают голосом.

**Открытые вопросы:**
1. Web Speech API в Chrome отправляет аудио в Google. Для B2B это риск конфиденциальности. В продакшене нужен MediaRecorder + серверный STT (он же снимает проблему оффлайна и Firefox/Safari).
2. 4 с тишины для конца ответа — гипотеза. Проверить на 5 пользователях.
3. ~~Порог 5 слов может отсекать короткие валидные ответы на Q4.~~ **Закрыт:** для Q3 и Q4 порог 2 слова, для Q1–Q2 — 5 (§5, AC-7.1, AC-7.2, AC-10.4).
4. «Дописать заново» в S18′ теряет ручные правки частичного текста. Допустимо для прототипа.
5. ~~Лимит 30 запросов в час~~ **Закрыт:** 30/час с IP пропускал 2 прохода в час из одного офиса. Теперь 60/час на анализ, 10/час на генерацию (§6).
6. ~~Порог 5 слов для Q3 не пропускал «пока не решили» (AC-10.4).~~ **Закрыт:** порог Q3 — 2 слова (§5).
